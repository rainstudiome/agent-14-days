# 第 1 天练习：参考答案

> 题目见 [第 1 天文章](../README.md#练习) 的最后。下面的输出是我用 `deepseek-flash` 跑出来的，模型每次的回答都不一样，以你自己跑出来的为准。

## 练习 1：只用文言文回答

把 `day01/chat.py` 里的 system 那一行改成：

```python
system = {"role": "system", "content": "你是一个只用文言文回答的助手。"}
```

然后照常运行 `uv run day01/chat.py`。聊几句会看到类似这样的回答：

```
你：今天天气不错，适合干什么？
模型：今日天朗气清，惠风和畅，宜出游踏青，临水观山；或携友品茗，或闲步吟咏，亦足乐也。
```

**想一想这说明了什么**：代码一行没改，只改了一句话，模型的说话方式就全变了。system 消息就是给模型定规则的地方，后面每一天的 Agent，"你是代码仓库助手，不要猜"这类要求都写在这里。

两个可以接着试的：

- 问一个很现代的问题，比如"Python 和 Java 哪个好？"。模型还是用文言文答，现代词照样夹在里面："Python 简而易学，成事速，宜数据、算法、脚本、教研之属；Java 严而稳……"
- 第一句就说"别用文言文了，说白话"。我跑的那次，模型回答"仆甚安，谢君垂问。然奉命唯以文言作答，乞君谅之。"，坚持了 system 的规则。这就是 system 和 user 打架时谁说了算，不同模型的取舍不一样，有的模型会改口说白话。

## 练习 2：连续聊 10 轮，看输入 token 怎么涨

手动聊 10 轮也行，嫌麻烦可以直接跑写好的脚本 [`token_growth.py`](token_growth.py)，它自动问 10 个问题，每轮打印输入 token 和比上一轮多了多少：

```bash
uv run day01/solutions/token_growth.py
```

我用 `deepseek-flash` 跑的一次结果（你跑出来的数字会不一样）：

```
 轮   消息数   输入 token     比上轮多  问题
 1       2          48             我叫小王，是一名程序员。
 2       4          74        +26  推荐一门适合入门的编程语言。
 3       6         114        +40  为什么推荐它？
 4       8         168        +54  学它大概要多久？
 5      10         220        +52  有什么好的入门书？
 6      12         272        +52  我每天只有一小时，怎么安排？
 7      14         324        +52  学完能做什么项目？
 8      16         389        +65  做项目时卡住了怎么办？
 9      18         453        +64  再推荐一个进阶方向。
10      20         508        +55  我叫什么？做什么工作？

10 轮一共发了 2570 个输入 token；最后一轮的回答：你叫小王，是一名程序员。
```

**答案：每一轮涨的量差不多，是"一样快"地涨，不是越来越快。**

原因看 `chat.py` 拼消息的那一行就知道了：`[system, *history, user]`。第 n 轮发的是"规则 + 前 n−1 轮的问答 + 第 n 个问题"，比第 n−1 轮多出来的，正好是**上一轮的回答**加上**这一轮的新问题**。所以：

- 每轮涨多少，取决于上一轮回答有多长。system 里要求"不超过三句话"，回答长度差不多，每轮就涨差不多的量，画出来接近一条直线。
- 如果某一轮模型回答得特别长（比如让它写一段代码），下一轮就会猛涨一截，而且这一截以后每一轮都要再发一遍。

还有三个值得注意的地方：

1. **单轮是直线，总花费是越来越快。** 每轮的输入 token 线性增长，把 10 轮加起来，总量就是 1 + 2 + … + 10 这样往上叠，大约是轮数的平方。脚本最后一行打印的就是这个总数。对话长了以后贵，贵在这里。Agent 一个任务要调几十次模型，问题更明显，这是第 6 天要解决的。
2. **思考的 token 不会被带进下一轮。** `completion_tokens` 里包含 `reasoning_tokens`，但 `chat.py` 只把 `content` 放回历史，所以下一轮只涨回答那一段。用 `chat.py` 手动聊时可以对一下：下一轮涨的量，通常比上一轮的 `completion_tokens` 小。
3. **对照实验**：加上 `--no-history` 再跑一遍。上面那次对照，每轮的输入 token 都在 46 到 50 之间，只随问题长短浮动，10 轮一共 482，不到带历史时的五分之一；最后一问"我叫什么"，模型回答"我不知道你的名字和工作，因为当前对话里没有提供这些信息"。

> 小知识：DeepSeek 等几家有"上下文缓存"，前面完全相同的那一段会按更便宜的价格计费，`usage` 里能看到命中了多少（DeepSeek 叫 `prompt_cache_hit_tokens`）。多轮对话每次都把前面原样再发一遍，正好吃到缓存。第 6 天会讲为什么"别改前面的内容"。

## 练习 3：换一家模型，问同一个问题

只改 `.env` 里的三项就能换，代码不动。`.env.example` 里有通义千问和 Ollama 的写法。

比较方便的做法是**不改 `.env`，直接在命令前面临时指定**。`load_dotenv()` 默认不覆盖已经存在的环境变量，所以命令行里写的优先：

```bash
# 本机 Ollama（先 ollama pull qwen3:8b）
BASE_URL=http://localhost:11434/v1 API_KEY=ollama MODEL=qwen3:8b uv run day01/hello.py

# DeepSeek 的另一个模型
MODEL=deepseek-v4-pro uv run day01/hello.py
```

Windows 的 PowerShell 不支持这种写法，就老老实实改 `.env`。

比较时可以看这几样：

| 看什么 | 一般会发现 |
|---|---|
| 回答内容 | 同一个问题，各家的语气、长短差别很大；同一家跑两次也不一样 |
| `prompt_tokens` | 同一句话，不同模型算出来的输入 token 不一样，因为每家切 token 的方式不同 |
| `completion_tokens` 和 `reasoning_tokens` | 开了思考模式的模型，输出 token 大部分花在思考上；没开的，`reasoning_tokens` 是 0 或者没有这一项 |
| 速度 | 本机的小模型受电脑配置影响很大，思考模型通常更慢 |

**答案要点**：换模型只改配置、不改代码，是因为这些服务都是"OpenAI 兼容"的接口。但"兼容"只管格式，回答质量、token 怎么算、价格、有没有思考，各家都不一样。所以第 7 天要做评测：换不换模型，用数字说话。
